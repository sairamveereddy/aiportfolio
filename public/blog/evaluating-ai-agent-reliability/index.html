As AI development shifts from static chat completions to autonomous agents (LangGraph, AutoGen, Claude Tool Use), the definition of software quality fundamentally shifts. In traditional software, functions are deterministic. In agentic systems, the LLM decides which tool to invoke, what arguments to supply, and whether the returned result satisfies the objective.

Without rigorous quantitative evaluation, agents in production succumb to catastrophic failure modes: schema hallucination, recursive loop thrashing, and unhandled tool exceptions.

1. Tool Selection Precision and Recall

Does the agent choose the correct tool for the given query? In our evaluation benchmark, we construct a curated test harness of 500+ diverse intent pairs. For each test case, we measure:

  • Tool Precision: The percentage of invoked tools that were genuinely necessary.
  • Tool Recall: Whether all necessary sub-tools were identified before attempting termination.
  • Over-Tooling Penalty: Unnecessary tool calls that increase user latency and API token cost.

2. Deterministic Schema Compliance

Even when an LLM selects the right tool name, it may hallucinate non-existent argument fields or misformat types (e.g. passing a stringified date when an ISO integer epoch was required).

Python (Pydantic Schema Guard for Tool Calls) 
from pydantic import BaseModel, Field, ValidationError

class DatabaseQueryToolSchema(BaseModel):
    table_name: str = Field(..., regex="^(claims|policies|prescriptions)$")
    limit: int = Field(default=50, le=500)
    filter_clause: str = Field(..., description="Sanitized SQL WHERE clause")

def safe_tool_executor(raw_arguments: dict):
    """Enforces strict schema validation before dispatching to database."""
    try:
        validated_args = DatabaseQueryToolSchema(**raw_arguments)
        return execute_query(validated_args)
    except ValidationError as err:
        # Return structured error back to the LLM agent to force self-correction
        return {
            "error": "SchemaValidationFailed",
            "details": err.errors(),
            "instruction": "Fix argument types according to the JSON schema."
        }

3. Loop Thrashing and Termination Limits

When an external tool returns an empty result set, naive agents often retry the exact same query repeatedly until hitting maximum iterations. We mitigate this using two architectural controls:

  1. State-Aware History Window: Injecting an explicit "repeated query warning" if an identical tool signature appears twice in conversation history.
  2. Hard Step Circuit Breaker: Terminating execution after N steps and gracefully asking the user for clarifying constraints.
