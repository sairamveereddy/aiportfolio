Inside Our Miro × n8n Hackathon-Winning Project: Architecture and Lessons Learned

By Sairam Kumar Reddy Veereddy · Lead AI & Workflow Automation Engineer

At the official Miro × n8n Hackathon (themed "From Diagram to Automation"), cross-functional teams were placed in a high-intensity, time-compressed sprint: build an AI automation that turns stalled visual diagrams into live executable workflows, pitch it in a strict 2.5-minute demo, and close the loop directly back onto the Miro canvas.

Our team, Strangers, formed on-site and captured 1st Place. In this article, I break down the event-driven system architecture, the challenges of low-latency canvas manipulation, and the key lessons for engineering production agentic workflows.

The Core Problem: Static Whiteboards vs Live Execution

Whiteboards like Miro are where modern engineering thinking happens: sprint topologies, database migrations, user feedback trees, and multi-service event routers. Yet once designed, they become static historical records. When changes occur in upstream services, the board goes stale. Conversely, updates on the board require manual developer translation into ticketing platforms or API calls.

The hackathon brief required completing a 3-stage loop:

  1. Design in Miro: Triggering from native board elements.
  2. Build in n8n: Parsing and orchestrating agentic logic.
  3. Write Back to Miro: Rendering structured AI outputs on the active canvas in real time.

Deep Dive: Direct Miro REST API Integration

One of our immediate technical constraints was that standard n8n integrations at the time did not feature rich canvas-drawing primitives out of the box. We solved this by implementing custom HTTP Request nodes within n8n that talk directly to Miro's REST API v2:

JavaScript (n8n Custom Function Node) 
// Normalizing Miro Webhook payload and calculating coordinate offsets
const item = $json.data.item;
const boardId = $json.data.boardId;

// Derive child card coordinates offset by 320px on the X-axis
const parentX = item.position?.x || 0;
const parentY = item.position?.y || 0;

return {
  boardId: boardId,
  parentId: item.id,
  parentText: item.data?.content || "Untitled Node",
  childX: parentX + 320,
  childY: parentY,
  timestamp: new Date().toISOString()
};

Once the AI agent synthesized the necessary actions, a subsequent n8n HTTP node posted the response back to Miro using bearer authentication:

HTTP POST (Miro REST API Payload) 
POST https://api.miro.com/v2/boards/{board_id}/sticky_notes
Content-Type: application/json
Authorization: Bearer {n8n_vault_miro_token}

{
  "data": {
    "content": "Action: Automated customer routing logic dispatched.
Status: Verified",

  },
  "style": {
    "fillColor": "light_green"
  },

    "origin": "center",

  }
}

Overcoming Rate Limits and Board Clutter

During our initial testing sprint, recursive webhooks posed a critical risk: when the n8n agent created a new sticky note on Miro, that creation fired another Miro webhook! This created a potential infinite loop.

We fixed this by appending a deterministic metadata signature:

Every automated note generated by n8n was tagged with a hidden metadata attribute origin: "agent-automation". Our n8n webhook listener immediately discarded any event carrying this flag, guaranteeing zero feedback recursion.

The 2.5-Minute Pitch

Judging criteria heavily penalized slide decks: judges wanted to see live whiteboard motion. During our demo, we typed a stalled workflow problem on a red sticky note, watched n8n process the event live on a split screen, and watched Miro dynamically spawn three green verified resolution cards with connecting arrows within 1.8 seconds.
