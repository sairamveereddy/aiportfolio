AI Urban Intelligence & Search

NYC Pulse: Urban Disruption Intelligence

"Elastic gives NYC Pulse memory. Mistral gives NYC Pulse reasoning."

GitHub Repo Architecture Case Study
Reasoning Engine Mistral Large
Memory Store Elasticsearch Cluster
Core Architecture Two-Phase Evidence Loop
Datasets NYC 311 Open Data + MTA GTFS

The Problem

When major urban infrastructure fails (such as an L train outage at Bedford Ave during evening rush hour), conventional emergency response relies on static alerts or naive single-shot LLM prompts. These single-shot prompts frequently hallucinate ripple effects without verifying whether displacement pressure actually causes secondary congestion, bus overloading, or noise complaints.

Technical Architecture & The Evidence Loop

Rather than asking the LLM to guess what happens next, NYC Pulse implements an autonomous Evidence Loop:

  1. Event Ingestion: Incident trigger details (location, line, severity) are parsed by the agent.
  2. Initial Investigation: Mistral Large calls Elasticsearch tools to retrieve nearby transit hubs (geo-distance) and historical 311 baseline complaint levels.
  3. Hypothesis Generation: Mistral formulates specific causal hypotheses (e.g., "M14 bus route overload will cause sidewalk crowding along 14th St").
  4. Evidence Verification: The agent autonomously issues follow-up queries against Elasticsearch to find historical signals supporting or contradicting the hypothesis.
  5. Grounded Output: A structured, evidential ripple-effect report is delivered to the Streamlit UI with confidence anchors.

My Technical Contributions

  • Implemented the autonomous tool-calling loop using Python and Mistral Large's native function-calling API.
  • Constructed the Elasticsearch indexing pipeline ingesting millions of NYC 311 complaints and GTFS transit station geometries.
  • Engineered geo-point bounding box filters and historical baseline aggregations to isolate statistically significant complaint surges.
  • Built the full-stack Streamlit interactive dashboard with scenario simulations.

Challenges & Engineering Decisions

Distinguishing correlation from baseline noise: Certain neighborhoods have chronically high complaint volumes. To prevent false alarms, I implemented historical aggregation queries in Elasticsearch that compute the z-score of complaint spikes against a 90-day neighborhood rolling baseline before accepting an LLM hypothesis.

JobNinjas.ai: AI Talent Platform

Production Cloud Platform: AWS + FastAPI + LangChain RAG + 8 n8n Workflows + Voice AI

GitHub Repo System Design Blog
Architecture Solo Full-Stack Cloud Infrastructure
Backend FastAPI + AWS (RDS, S3, SES, Cognito)
Automations 8 Production n8n Workflows
Voice Interface WebRTC + Vapi + Faster-Whisper

The Problem

Job applicants face fragmented, high-friction processes: resume customization, portfolio curation, cover letter writing, and interview prep are scattered across disconnected apps with zero continuity, high latency, and generic outputs.

Technical Architecture

Designed and shipped single-handedly, JobNinjas.ai combines an asynchronous FastAPI backend hosted on AWS with:

  • AWS Cognito & RDS PostgreSQL: Secure authentication, user dossier storage, and role-based permissions.
  • LangChain / LangGraph Agentic RAG: Indexes candidate experiences into ChromaDB and generates ATS-tailored resume bullets with verifiable citation groundings.
  • 8 Automated n8n Workflows: Manages document parsing queues, webhook routing, transactional notifications, and synchronization between services.
  • Real-Time Voice Streaming: Integrated WebRTC voice sessions using Vapi, faster-whisper STT, and Coqui/StyleTTS2 for conversational interview prep.

Challenges & Engineering Decisions

Decoupling compute-heavy RAG from low-latency voice: Running document retrieval inside a real-time voice loop creates intolerable latency. I engineered an asynchronous event queue where RAG queries pre-compute structured bullet adaptations in the background, allowing the voice agent to pull pre-indexed answers within sub-second conversational windows.

Conversational AI & WebRTC

AI Talking Portfolio: Voice Concierge with Site Control

Realtime Audio Streaming, OpenAI Realtime API, and Synchronized Client DOM Manipulation

GitHub Repo Agent Reliability Blog

The Problem

Standard online resumes and portfolios are passive text documents. Hiring managers and technical reviewers want to test conversational agility, technical depth, and actual live system responsiveness in real time.

Technical Architecture

The portfolio establishes a bi-directional WebRTC connection via a secure Node.js backend to the OpenAI Realtime API. The agent is equipped with a custom function-calling tool (navigate_site). When the visitor asks a question, the agent issues a tool call on the WebRTC data channel instructing the client browser to scroll to and highlight the relevant section (e.g. CVS Pharmacy experience, research publications, or hackathon achievements) while speaking naturally.

Challenges & Engineering Decisions

Strict factual grounding: To prevent prompt drift or fabricated accomplishments, the system prompt contains strict boundary instructions enforcing that any unverified detail be explicitly declined and redirected to verified resume facts.
